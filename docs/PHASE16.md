## 2. Architecture decisions

* **One server with Docker + Caddy** instead of a platform-specific setup: portable, cheap, one config you control. Other hosts: `docs/DEPLOYMENT.md` section 7. (Assumption: you told me nothing about hosting. Tell me if you chose Render, Railway or similar and I will adapt.)
* **Admin web and API on one origin** (`/api`), so the refresh cookie is first-party and the admin panel needs no CORS.
* **`DIRECT_URL` only in `.env.migrate`.** The Prisma schema declares `directUrl`; the runtime image fills it from `DATABASE_URL` when absent, so the API container never holds owner credentials.
* **Release builds fail closed** (no debug signing, no non-https API).

## 4. Manual verification
1. `docker compose -f infra/deploy/docker-compose.prod.yml config` (with your three env files in place) prints without errors.
2. `run --rm cli npm run preflight` with the unedited example file FAILS (placeholders); with your real file it passes.
3. After `up -d`: `ps` shows `api` healthy, `smoke-test` passes.
4. Open `https://admin.<domain>/login`, sign in with MFA. Reload on `/salons`: the page loads (SPA fallback). DevTools > Network: calls go to `/api/v1/...` on the same host; no CSP errors in the console.
5. Android: `flutter build appbundle --release` WITHOUT `key.properties` must fail with the "needs android/key.properties" message; with it, an `.aab` appears. A release build without `--dart-define=API_BASE_URL=https://...` must crash at start with the https message (this is intended).
